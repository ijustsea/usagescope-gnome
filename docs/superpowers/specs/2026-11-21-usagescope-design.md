# UsageScope GNOME v1 design
Approved scope: implement the previously discussed local GNOME quota indicator in this repository. Work directly on main per user instruction. No custom backend, no model requests, no automatic installs, no credential reads by UsageScope.
Target: GNOME Shell 51 / GJS 1.90 on Fedora, TypeScript emitted ESM; Node only for development.
Architecture: pure core validates unknown payloads, formats quota windows, stores last-good snapshots; CodexController owns at most one stdio child with allowlisted RPCs, releases it after quota reads and retains it during managed browser login; ClaudeController watches private bounded runtime snapshots emitted by a standalone GJS bridge. UI uses St/Clutter, GSettings and accessible provider sections.
Public contracts: src/core/types.ts. Controllers implement refresh/connect/stop and publish ProviderView. Codex options {executable:string,pollSeconds:number,publish:Publish,openUri:(uri:string)=>void}; Claude options {publish:Publish}. Both controllers start via start():void. Claude connect opens setup guidance in UI (no blind overwrite of user's settings).
Security invariants: no sh -c or eval for app commands, executable paths resolved and checked; no browser cookie/token storage or model turns; auth URLs HTTPS with exact official host allowlist, no credentials/nonstandard ports; request/frame/input/directory bounds; private local files with no symlink-following; explicit schema validation and source selection; bounded logs with no raw payloads; cancellation and generation guards; owned child terminated on stop.
Claude integration: supported CLI sign-in through terminal command instructions, statusline integration via explicit helper CLI that previews/applies/backups/restores only user-approved change and preserves existing renderer. Export failures must not corrupt existing renderer stdout. Runtime private directory under XDG_RUNTIME_DIR; immutable snapshots ordered by local invocation start, latest per explicit session, expiration is not reset. No cross-login persistence.
State: zero is valid, null/missing not 100. Valid full payload omits a window => retire current window; malformed preserves last good as historical. Last receipt is not server observation. Source/account changes cannot retain previous current data. Codex low alert only threshold crossing <20 rearm >=25, no initial sample/reset/Claude desktop alerts.
UI: panel percentages and menu showing source receipt age/errors; connection button, cancelable Codex login, refresh Codex, Claude setup instructions, monitoring toggles and settings. Default no provider acquisition until explicitly enabled; enabling existing login may query quota but no model calls.
Distribution: zip built from tested JS, metadata, CSS, compiled schema, bridge/core only. No bundled binary/node_modules/credentials, no self-update. README + security document include installation, integration, limitations and actual verification coverage.

## User-authorized v0.2 UI revision

The main UI is now compact provider cards with remaining-quota bars: ChatGPT blue, Claude orange, <=30% red. Both providers alert on new reports crossing below30 and rearm at35; Claude describes last reported values without server-freshness inference. Subscription plan tiers replace the requested AI-model-name interpretation. Codex reported planType is used; explicit trusted Claude auth/status may supply subscriptionType through a bounded private300s cache. Main website buttons open fixed official sign-in/sign-up sites only; local CLI setup remains in collapsed settings. Whole-popup scrolling bounds the menu; no hidden label may leave a blank row. README uses plain numeric installation steps and separates Wayland logout/login from enable.
